## 남은 검토 게이트

1. **화면:** 실제 VS Code에서 탭·접힘·자동 줄바꿈·고대비와 선택·검색·진단·디버거 표시를 비교한다. 경계가 어긋나거나 텍스트가 읽기 어려우면 배경 범위와 팔레트를 조정한다.
2. **오류 복구:** 입력 중 빠른 오류·복구, 열린 분할 편집기, 문서 닫힘에서 오래된 장식과 캐시가 남지 않는지 확인한다.
3. **성능:** 10,000행의 이벤트부터 `setDecorations` 반환까지 p95, 최초 분석, 긴 단일 행·깊은 중첩·오류 다발 파일을 기록해 20,000행·2MB 제한 후보를 재평가한다.
4. **배포:** VSIX는 설치 가능하지만 publisher가 정의되지 않아 `undefined_publisher`로 설치됐고 라이선스 파일 경고가 있다. 공개 배포 전에 둘을 확정한다.

설계 검토에서 위 항목을 **통과로 표시하지 않았다**. 결과에 따라 [상세 설계안](../docs/detailed-design.md)의 표시 방식과 수치를 수정한 뒤 설계를 확정한다.

## 2026-10-01 기술 검증 후 재검토

[기술 검증](technical-validation.md)과
[실제 화면 캡처](visual-validation.md)를 주장별 근거로 대조했다.
Windows의 검증 결과를 다른 플랫폼이나 최종 배포 결과로 넓혀
해석하지 않았다.

| 중요도 | 검토 의견 | 설계 반영 | 남은 검증 |
| --- | --- | --- | --- |
| 높음 | 오류가 많은 Python 6,000행의 단일 분석이 184.08ms였다. 내용 변경마다 즉시 동기 분석하면 연속 입력을 막을 수 있다. | 변경 즉시 구문 장식을 비우고 마지막 입력 75ms 후 버전 확인을 거쳐 분석한다. 대기 상태와 분석 오류를 구별한다. | 구현 후 빠른 연속 입력과 오래된 결과의 잔류 확인 |
| 높음 | 2,000단계 TypeScript 중첩에서 파서 호출이 스택 초과로 실패했다. 20,000행·2MB만으로 안전 범위를 설명할 수 없다. | 예외를 `분석 오류`로 표시하고 구문 장식을 비운다. 일반 파일 크기 제한과 별개임을 문서화한다. | Host에서 깊은 입력 후 다른 문서의 정상 동작 확인 |
| 중간 | 전체 범위 한 개의 배경 장식은 화면 밖·접힘 위치를 과도하게 칠할 수 있었다. | `visibleRanges` 교집합과 실제 보이는 경계 행만 사용한다. | 접힘·줄바꿈 화면 재확인 |
| 중간 | 기존 최소 VS Code `^1.138.0`은 통합 검증 버전과 달랐다. | 첫 배포 최소 버전을 검증한 `^1.140.0`으로 정한다. | 최종 manifest·VSIX 확인 |
| 중간 | 색상·모드별 불투명도는 화면 검증 전에 고정하면 가독성을 과장할 수 있다. | 모드와 팔레트의 의미·우선순위를 고정하고 정확한 색상값은 MVP 화면 비교로 확정한다. | 밝은색·어두운색·고대비 비교 |

현재 설계는 MVP 구현 기준으로 사용할 수 있다. 75ms 예약 분석,
모드·팔레트, 이동·선택 명령의 구현과 화면 검증은 미완료다.
이 표는 출시 승인이나 최종 검증 통과를 뜻하지 않는다.
