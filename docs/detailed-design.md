# Mark Your Scope 상세 설계안

작성일: 2026-10-01. 상태: 첫 출시 MVP의 **확정 설계 기준**.
[설계 검토](../.worknotes/design-review.md)와
[기술·화면 검증](../.worknotes/technical-validation.md)의 결과로
분석 제한과 기본 표시값을 확정했다. 최종 게시 결과는 별도로 기록한다.

## 결정과 범위

사용자가 2026-10-01에 승인한 기획 기준은 제품 가칭 **Mark Your Scope**, 첫 출시의 JS/TS·Python·JSON 구문 범위와 YAML 들여쓰기 표시, 기본 **Balanced** 모드다. [제품 기획안](product-plan.md)의 나머지 제안 중 팔레트 수치, 최소 VS Code 버전, 대용량 제한은 기술 검증 후 확정한다. 이 문서는 목표 동작이며 현재 구현 목록이 아니다.

첫 출시는 로컬 문서의 들여쓰기와 커서가 속한 구문 범위를 읽기 쉽게 표시한다. 코드 변경, 변수 참조 분석, 자체 괄호 색칠 엔진, 태그·혼합 언어, Notebook·diff 편집기, 전체 문서 감광은 범위에 넣지 않는다.

## 데이터 모델과 언어 규칙

`Scope`는 `{ kind, start, end, level }`이다. `start`는 포함하고 `end`는 포함하지 않는 문서 UTF-16 오프셋이다. `level`은 `block` 또는 `expression`이며 괄호 깊이나 들여쓰기 깊이와 공유하지 않는다. 같은 위치의 후보는 짧은 범위, 더 안쪽 시작점, 종류 순으로 정렬한다. 기본 `block` 목표는 표현식을 건너뛰고 가장 안쪽 블록을 고른다. `expression` 목표는 블록과 표현식 중 가장 안쪽을 고른다. 상위 범위 명령은 이 후보 목록의 다음 항목으로 이동한다.

| 언어 | 블록 후보 | 표현식 후보 | 오류 처리 |
| --- | --- | --- | --- |
| JavaScript / TypeScript | 함수·클래스·조건·반복·예외 블록 | 호출·배열·객체 | TypeScript 공개 구문 진단과 닫는 구분자를 함께 확인한다. 진단을 포함하는 후보는 제거하고 독립된 정상 후보는 유지한다. |
| Python | 함수·클래스·조건·반복·예외·`with` | 호출·리스트·딕셔너리 | Lezer 오류 노드를 포함하는 후보를 제거한다. 블록 끝은 파서의 본문 범위를 따른다. |
| JSON | 객체·배열 | 별도 표현식 없음 | 표준 `JSON.parse`가 실패하면 전체 구문 범위를 비운다. 후행 쉼표와 주석도 허용하지 않는다. |
| YAML | 없음 | 없음 | 선행 공백의 표시 열만 계산한다. 구문 범위를 추정하지 않는다. |

JSX/TSX, JSON with Comments, 다른 텍스트 언어에는 첫 출시 구문 범위를 약속하지 않는다. 단, 제외 설정이 아니면 들여쓰기 표시를 허용한다. 빈 줄·주석의 포함 여부는 파서가 반환한 범위에 따른다. Python에 존재하지 않는 닫는 괄호를 생성하지 않는다. 여러 줄 인자 정렬을 별도 블록으로 취급하지 않는다.

분석 결과는 `supported`, `unsupported`, `unresolved`, `failed` 중 하나다. 구문 오류가 있지만 독립된 정상 후보가 있으면 `unresolved`와 그 후보를 함께 반환한다. 오류 입력에서 닫는 문자만 남았다는 이유로 상위 범위를 그리지 않는다. 문서가 제한을 초과하면 분석을 실행하지 않고 `limited` 표시 상태로 다룬다.

## 상태 흐름과 소유권

| 소유자 | 데이터 | 갱신·해제 |
| --- | --- | --- |
| 문서 URI·버전 | 분석 결과와 분석 시간 | 내용 변경 시 이전 버전 폐기, 문서 닫힘 시 해제 |
| `TextEditor` 인스턴스 | 주 커서의 기준 위치, 상위 범위 단계, 선택된 범위 | 커서 이동·문서 변경 시 기본 단계로 복귀, 편집기 닫힘 시 해제 |
| 확장 활성 세션 | 일시적인 범위 강조 토글 | 창 재시작 시 설정 기본값으로 복귀 |
| 워크스페이스 설정 | 모드·팔레트·언어 제외·세부 옵션 | VS Code 설정 우선순위와 언어별 재정의를 따름 |

문서 내용 변경 → 캐시 무효화와 기존 구문 장식 즉시 제거 → 마지막 입력 후 75ms에 해당 문서를 한 번 분석·재표시한다. 대기 중의 커서 이동은 들여쓰기와 활성 편집기 상태만 갱신하고 동기 파싱을 새로 시작하지 않는다. 대기 상태에는 `Scope: 분석 중`을 표시한다. 예약 실행 직전에 문서 URI·버전을 확인하고, 닫힌 문서의 예약은 취소한다. 분할 편집기의 문서 분석은 공유하지만 커서와 상위 단계는 공유하지 않는다. 활성 편집기 변경 시 상태 표시줄을 새 편집기로 갱신하고, 활성 편집기가 없으면 숨긴다. 화면 범위, 탭 크기, 테마, 관련 설정 변경은 분석이 아니라 장식만 다시 계산한다.

입력 이벤트가 연속될 때 오래된 장식은 즉시 지우고 현재 버전 결과만 적용한다. 분석 예외는 출력 채널에 남기고 해당 문서의 구문 장식을 지운다. 깊은 중첩 등 파서가 처리하지 못한 입력은 범위를 추정하지 않고 `분석 오류`로 표시한다. 한 문서의 실패를 다른 문서로 전파하지 않는다.

## 표시와 접근성

표시 우선순위는 `enabled=false` 또는 제외 언어 → 모두 숨김, `mode=off` → 모두 숨김, 세션 토글 꺼짐 → 구문 장식만 숨김, 그 밖에는 모드 프리셋과 명시적 세부 설정 순이다. 명시적 세부 설정은 해당 기능의 모드 기본값을 덮어쓴다. 설정의 언어별·워크스페이스별 우선순위는 VS Code가 계산한 유효값을 사용하며, 명시 여부가 필요한 항목은 `inspect`로 확인한다.

| 모드 | 들여쓰기 기본값 | 범위 기본값 |
| --- | --- | --- |
| Balanced | 낮은 채도의 선 | 옅은 배경과 시작·끝 경계 |
| Structure | 단계별 공백 배경 | 경계 중심 |
| Focus | 최소 선 | 배경과 경계의 대비를 높임 |
| Off | 숨김 | 숨김 |

들여쓰기 선은 보이는 논리 행에서만 만들고, 탭의 표시 폭은 편집기 `tabSize`로 계산한다. 범위 배경도 선택한 범위와 `visibleRanges`의 교집합에만 적용한다. 시작·끝 경계는 실제 경계 행이 보일 때만 그린다. 접힘과 자동 줄바꿈에서 선이 어긋나면 먼저 경계 중심 표시로 축소한다. 전체 파일에 하나의 큰 배경 장식을 전달하는 방식은 화면 검증 후 유지 여부를 결정한다.

팔레트는 `auto`, Dark Soft, Light Soft, High Contrast, Monochrome를 제공한다. `auto`는 활성 테마 종류를 따라간다. 정확한 색과 불투명도는 실제 VS Code 밝은색·어두운색·고대비 테마에서 선택·검색·진단·디버거 표시와 함께 비교해 정한다. 텍스트 전경색은 바꾸지 않는다. 범위 종류와 행 번호를 상태 표시줄에도 제공하고, 고대비에서는 배경보다 경계를 우선한다. 다른 확장의 설정은 자동 변경하지 않는다.

| 상태 | 활성 편집기 상태 표시줄 |
| --- | --- |
| 정상 범위 | `Scope: if · L12–L20`처럼 종류와 논리 행 표시 |
| 정상 코드의 범위 밖 | `Scope: 범위 없음` |
| 오류 위치의 불확실한 범위 | `Scope: 구문 확인 불가` |
| 미지원 언어 | `Scope: 들여쓰기만 표시` |
| 분석 예외 | `Scope: 분석 오류` |
| 분석 제한 | `Scope: 파일 크기 제한` |
| 주변 행 모드 | `Scope: 주변 L12–L18`처럼 구문이 아님을 표시 |

`Scope: 분석 중`은 실제 비동기 작업이 있을 때만 사용한다. 사용자가 끈 상태에서는 상태 표시줄을 숨긴다.

## 명령과 설정 계약

| 명령 | 동작과 상태 변화 |
| --- | --- |
| Toggle Scope Highlight | 현재 창 세션의 구문 장식만 일시 전환한다. 들여쓰기 설정은 유지한다. |
| Choose Display Mode | 네 모드 중 하나를 Quick Pick으로 선택해 설정에 저장한다. 취소하면 변경하지 않는다. |
| Choose Palette | 후보 위·아래 이동 중 활성 편집기에 미리보기, 취소 시 원래 표시 복귀. 확정 후 사용자 또는 워크스페이스 위치를 고른다. |
| Focus Parent Scope / Reset Scope Focus | 편집기별 후보 목록을 한 단계 확장 / 기본 후보로 복귀한다. 일반 커서 이동과 내용 변경 시 확장 단계를 지운다. |
| Go to Scope Start / End | 선택된 범위의 시작 / 마지막 실제 문자 위치로 이동한다. 이 명령으로 이동한 경우 선택된 범위는 유지한다. |
| Select Scope | 선택된 구문 범위를 편집기 선택 영역으로 만든다. 다른 커서는 변경하지 않는다. |

명령에는 기본 단축키를 배정하지 않는다. 팔레트 저장 위치를 묻는 단계는 사용자가 확정한 후에만 나온다. 워크스페이스가 없으면 사용자 설정만 제공한다. 설정 초기화는 선택한 저장 위치의 값만 제거한다.

`markYourScope.enabled`, `mode`, `indentation.style`, `focus.target`, `focus.contextLines`, `palette`, `indentation.warnings`, `excludedLanguages`를 기획안의 이름과 타입으로 노출한다. 주변 행 목표는 구문 분석 결과와 분리해 위아래 `contextLines` 논리 행을 선택한다. 잘못된 사용자 색상값은 해당 값만 기본값으로 대체하고 설정 문제를 알린다. 설정 명세와 실제 `package.json`은 구현 단계에서 함께 갱신한다.

`indentation.warnings`의 기본값은 `off`다. `mixed`는 선행 들여쓰기에
탭과 공백이 함께 있는 행을 표시한다. `all`은 이에 더해 들여쓰기의
표시 열이 `tabSize`의 배수가 아닌 행을 표시한다. 빈 행은 표시하지
않는다. 표시는 참고용 장식과 호버 설명이며 언어 진단이나 자동 수정은
만들지 않는다. `indentation.style=off`에서도 사용자가 경고를 켰다면
경고 장식은 표시한다.

## 실행 제한과 검증 계획

출시 초기 분석 제한은 20,000행 또는 UTF-8 2MB 초과다. 제한 초과 시 구문 분석만 건너뛰고 보이는 행의 들여쓰기 표시는 유지한다. 이 값은 일반 파일 크기 제한이며 파서의 중첩 한도를 보증하지 않는다. 파서 스택을 넘는 깊은 중첩은 분석 오류 상태로 안전하게 종료한다. 오류가 매우 많은 Python 문서에서 단일 분석이 느릴 수 있으므로 입력을 합쳐 75ms 뒤 분석한다. 커서 이동 시 문서를 다시 파싱하지 않는다.

`performance.now()`로 선택 이벤트 시작부터 마지막 `setDecorations` 호출 반환까지 10,000행 샘플의 p95를 측정하고 목표값 50ms와 비교한다. 이는 API 호출까지의 시간이며 실제 화면 그리기 완료 시간으로 표기하지 않는다. 최초 분석 시간과 장식 개수도 따로 기록한다. 화면 반영과 기존 표시 공존은 Extension Development Host에서 실제 화면을 확인한다. Windows에서 통과한 검사만 다른 플랫폼·Remote·웹 확장 지원의 근거로 쓰지 않는다.

현재 확인된 검사는 [기술 검증 기록](../.worknotes/technical-validation.md)과 [화면 검증 기록](../.worknotes/visual-validation.md)에 남긴다. Windows x64의 VS Code 1.140.0에서 확인했으므로 첫 배포의 최소 버전은 `^1.140.0`으로 정한다. 다른 플랫폼과 Remote·웹 확장은 각 환경에서 별도 검증하기 전까지 지원을 약속하지 않는다. 화면·성능 제약이 추가로 발견되면 장식 방식과 제한을 다시 검토한다.
