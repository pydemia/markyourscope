# Mark Your Scope 제품 기획안

작성일: 2026-10-01. 상태: 제품명·첫 출시 언어·기본 Balanced 모드의
기획 기준 확정, 기술 검증과 [상세 설계안](detailed-design.md) 진행 중.
실제 화면·성능·출시 검증 전.

## 제품 목적과 기획 범위

코드를 읽거나 수정할 때 들여쓰기 단계, 구문 시작·끝, 현재 커서가 속한
블록을 빠르게 구별할 수 있는 VS Code 확장이다. 프로젝트 디렉터리명을
기준으로 제품 가칭을 **Mark Your Scope**로 둔다.

사용자가 요청한 기능은 Focus의 편집 범위 강조, Rainbow Brackets의 괄호
구별, Indent Rainbow Palettes의 팔레트 선택, indent-rainbow의 들여쓰기
시각화다. 사용자는 2026-10-01에 가칭 Mark Your Scope, 첫 출시의
JS/TS·Python·JSON 구문 범위와 YAML 들여쓰기 표시, 기본 Balanced 모드를
설계 기준으로 승인했다. 나머지 기본값·출시 세부 사항은 제안 상태다.

현재 저장소에는 [확장 프로토타입](../src/extension.ts)과 자동 테스트가
있다. 범위 분석, 들여쓰기 선, 기본 범위 장식, 상위 범위·초기화 명령을
실험 중이다. [기술 검증 기록](technical-validation.md)의 자동 테스트와
확장 호스트 검사는 통과했지만 장식의 실제 화면 품질과 출시 범위는
확인하지 않았다. 아래 사용 경험과 명령·설정은 목표 동작이며 현재
구현된 기능 목록이 아니다.
여기서 ‘범위’는 시각적으로 식별할 구문 영역을 뜻한다. 변수의 유효 범위나
참조 관계를 분석하는 기능은 포함하지 않는다.

## 사용자 작업과 표시 원칙

주요 작업은 중첩된 조건문·반복문 읽기, 긴 함수의 일부 수정, 닫는 괄호가
어디에 대응하는지 확인, Python 블록과 여러 줄 표현식 구별이다.

세 종류의 깊이를 구분한다.

- **들여쓰기 깊이**: 화면에서 선행 공백이 차지하는 열 수를 기준으로 계산한다.
- **구문 깊이**: 언어 분석 결과에서 블록·표현식이 중첩되는 단계다.
- **괄호 깊이**: 괄호 쌍이 중첩되는 단계다. 내장 색상 규칙과 다를 수 있다.

여러 줄 함수 호출의 인자 정렬은 들여쓰기 단계가 커져도 새 블록이 아니다.
한 줄의 `call(a, [b, c])`는 괄호가 중첩되어도 들여쓰기 단계가 늘지 않는다.
따라서 ‘같은 깊이니까 같은 색’이라는 규칙을 세 종류에 공통 적용하지 않는다.

들여쓰기 색은 정렬을 읽는 데 사용한다. 현재 구문의 시작·끝 표시와 범위
배경은 하나의 강조 색을 공유한다. 괄호 전체의 색은 내장 기능에 맡기되
현재 선택한 범위의 구분자에는 별도 테두리 등으로 대응 관계를 보강한다.

## 기본 사용 경험

설치 후 지원 문서를 열면 낮은 채도의 들여쓰기 선을 표시한다. 커서를
이동하면 가장 가까운 구문 범위에 옅은 배경과 시작·끝 표시가 붙는다.
텍스트 색상과 문서 내용은 바꾸지 않는다.

기본 블록 모드는 함수, 클래스, 조건문, 반복문 등의 구조를 선택한다.
표현식 모드에서는 함수 호출, 배열, 객체 등 더 작은 범위를 선택한다.
주변 행 모드는 커서 위아래의 고정 행만 강조하며 구문 범위로 설명하지 않는다.
범위가 확인되지 않을 때 주변 행 모드로 자동 전환하지 않는다.

예를 들어 다음 코드의 `save(item)`에 커서를 놓으면 기본 모드는 `if`
블록을 강조한다. 상위 범위 명령을 한 번 실행하면 `for` 블록을 강조한다.

```python
def process(items):
    for item in items:
        if item.valid:
            save(item)
```

Python에서는 블록 헤더와 본문 끝을 표시하고 닫는 괄호를 만들어 표시하지
않는다. 빈 줄과 주석은 언어 분석기가 결정한 범위에 포함한다.

### 표시 모드

| 모드 | 들여쓰기 | 현재 범위 | 사용 목적 |
| --- | --- | --- | --- |
| Balanced · 기본 | 옅은 선 | 옅은 배경과 시작·끝 | 일상적인 편집 |
| Structure | 단계별 공백 배경 | 경계 중심 | 중첩 구조 읽기 |
| Focus | 최소 표시 | 현재 범위 강조 | 긴 블록의 일부 수정 |
| Off | 숨김 | 숨김 | 일시 중지 |

범위 밖 텍스트 감광은 기본적으로 끈다. 선택 영역, 검색 결과, 오류 밑줄,
디버거 현재 행의 가독성을 먼저 보장해야 한다. 감광 옵션은 충돌 검증 후
후속 버전에 포함할 수 있다.

색상만으로 상태를 전달하지 않는다. 현재 범위는 경계와 상태 표시줄의
종류·행 범위로 함께 식별한다. 흑백·고대비 프리셋에서는 배경보다 선과
경계를 우선하고 움직이는 전환 효과는 넣지 않는다.

## 명령과 설정 흐름

별도 사이드바 대신 명령 팔레트, Quick Pick, VS Code 기본 설정 화면을
사용한다. 상태 표시줄은 활성 편집기에만 `Scope: if · L12–L20`처럼 표시한다.
이름은 분석 결과가 있을 때만 보여 주며 추정한 함수명을 만들지 않는다.

| 명령 | 동작 |
| --- | --- |
| Toggle Scope Highlight | 범위 강조를 일시적으로 켜거나 끔 |
| Choose Display Mode | Balanced / Structure / Focus / Off 선택 |
| Choose Palette | 현재 문서에서 미리보기 후 설정 저장 |
| Focus Parent Scope | 선택 범위를 한 단계 상위로 확장 |
| Reset Scope Focus | 현재 커서의 기본 범위로 복귀 |
| Go to Scope Start / End | 선택 범위 시작·끝으로 이동 |
| Select Scope | 선택 범위를 실제 편집기 선택 영역으로 지정 |

기본 단축키는 배정하지 않는다. 사용자가 기존 키 설정과 충돌 없이 지정할
수 있도록 모든 명령을 등록한다. 상위 범위 선택은 커서를 옮기면 해제한다.
시작·끝 이동 명령은 선택한 범위를 유지해 다시 반대쪽으로 이동할 수 있다.

팔레트 선택은 취소 시 원래 표시로 복귀한다. 확정할 때 사용자·워크스페이스
저장 위치를 선택하고 파일이 없는 워크스페이스에서는 가능한 위치만 제공한다.
확장 전용 설정은 VS Code의 설정 우선순위와 언어별 재정의를 따른다.
‘초기화’는 선택한 설정 위치의 값을 제거하며 다른 위치의 값을 덮어쓰지 않는다.

다음 설정명은 제안이다. 실제 manifest 설계에서 타입·범위·기본값을 확정한다.

| 설정 | 제안 기본값 | 의미 |
| --- | --- | --- |
| `markYourScope.enabled` | `true` | 전체 표시 활성화 |
| `markYourScope.mode` | `balanced` | 표시 모드 |
| `markYourScope.indentation.style` | `line` | `line` / `background` / `off` |
| `markYourScope.focus.target` | `block` | `block` / `expression` / `lines` |
| `markYourScope.focus.contextLines` | `3` | 주변 행 모드에서 위아래 각각의 행 수 |
| `markYourScope.palette` | `auto` | 테마 종류에 맞는 확장 프리셋 |
| `markYourScope.indentation.warnings` | `off` | 탭·공백 혼합 등 참고 표시 |
| `markYourScope.excludedLanguages` | `["plaintext", "markdown"]` | 기본 제외 언어 |

프리셋은 Dark Soft, Light Soft, High Contrast, Monochrome부터 제공한다.
정확한 색상값과 투명도는 실제 테마에서 비교해 확정한다. 사용자 지정
색상값이 잘못되면 해당 항목을 기본값으로 대체하고 설정 문제를 알려 준다.

## 언어별 출시 범위

| 언어 | 첫 출시 목표 | 주의할 경계 |
| --- | --- | --- |
| JavaScript / TypeScript | 들여쓰기와 블록·표현식 범위 | 문자열, 주석, 정규식, 템플릿 리터럴, 미완성 입력 |
| Python | 들여쓰기와 함수·조건문·반복문 범위 | 여러 줄 표현식, 문자열, 데코레이터, 주석·빈 줄 |
| JSON | 들여쓰기와 객체·배열 범위 | 객체의 중괄호를 함수 블록으로 취급하지 않음 |
| YAML | 들여쓰기 표시 | 첫 출시에서는 구문 범위를 보장하지 않음 |
| 기타 텍스트 언어 | 설정에 따른 들여쓰기 표시 | 구문 강조는 미지원으로 표시 |

JSX/TSX, HTML, Vue 같은 태그·혼합 언어는 후속 범위로 둔다. 단순 `<`와
`>` 매칭으로 태그와 비교 연산자를 처리하지 않는다. Notebook 셀과 diff
편집기도 후속 범위다. Remote SSH 및 웹 확장은 각각 별도 통합 검증 후
지원 여부를 명시한다.

## 경계 상황과 호환성

- 입력 중 문법이 깨지면 확인 가능한 범위만 표시한다. 범위가 불확실하면
  강조를 지우고 `Scope: 구문 확인 불가`처럼 원인을 드러낸다. 실제 비동기
  분석이 진행 중일 때만 `Scope: 분석 중`을 사용한다.
- 미지원 언어는 `Scope: 들여쓰기만 표시`로 안내한다. 정상적인 최상위
  위치에 범위가 없는 상태와 분석 실패를 구별한다.
- 여러 커서는 주 선택의 활성 위치만 범위 강조에 사용한다. 다른 커서와
  선택 영역은 편집기의 기존 표시를 유지한다.
- 분할 편집기는 같은 문서를 열어도 커서·선택 범위를 각각 보관한다.
- 줄바꿈은 논리 행 기준으로 계산한다. 접힌 코드와 화면 밖 범위 때문에
  전체 화면이 잘못 칠해지지 않도록 장식을 제한한다.
- 탭은 문자 수가 아닌 편집기의 `tabSize`에 따른 표시 열로 계산한다.
  단위의 배수가 아닌 공백은 정렬일 수 있으므로 기본 오류로 판정하지 않는다.
- 큰 파일에서는 범위 분석을 제한하고 들여쓰기만 유지할 수 있다.
  자동 제한 이유를 상태 표시줄에서 확인할 수 있게 한다.
- 기존 Focus·indent-rainbow 장식이 겹치면 설정 안내를 제공한다.
  다른 확장을 자동으로 끄거나 사용자 설정을 자동 변경하지 않는다.
- 내장 괄호 색상, Sticky Scroll, 들여쓰기 가이드의 설정을 자동 변경하지
  않는다. 추천 설정을 보여 줄 때 적용 대상과 변경 내용을 먼저 표시한다.

## 구현 방향과 먼저 검증할 항목

TypeScript 확장으로 구현하고 문서를 읽어 편집기 장식만 적용한다.
코드 전송, LLM 호출, 계정, 서버는 제품 기능에 필요하지 않다.

공식 [VS Code API](https://code.visualstudio.com/api/references/vscode-api)의
`createTextEditorDecorationType`, `setDecorations`, `visibleRanges`를 활용하는
방향이다. 문서 변경 시 분석 결과를 갱신하고 커서 이동 시 저장된 범위에서
선택한다. 커서 이동마다 전체 문서를 다시 분석하지 않는다.

언어 분석 결과는 문서 URI·버전별로 저장하며 표시 상태는 편집기별로
관리한다. 현재 프로토타입은 동기식으로 분석한다. 비동기 방식으로
전환한다면 완료 시 문서 버전과 편집기 상태를 확인해 이전 결과가 새
내용이나 다른 편집기에 적용되지 않도록 한다. 닫힌 문서의 분석 결과와
사용하지 않는 장식 객체는 해제한다.

프로토타입은 JS/TS·JSON에 TypeScript AST, Python에 `@lezer/python`을
사용한다. JS/TS는 TypeScript 구문 진단과 닫는 구분자로 오류가 포함된
범위를 제외하고, JSON은 표준 파싱 실패 시 구문 범위를 비운다. 두 파서의
출시용 선택은 확정하지 않았다. 복구 입력과 실제 장식 갱신은 추가 검증이
필요하다.
정규식만으로 문자열·주석·중첩 구문을 처리하지 않는다. Folding Range와
Document Symbol은 보조 정보로 검토하되 모든 표현식·블록의 정확한 범위를
보장한다고 가정하지 않는다. 편집기 내부 괄호 트리를 공개 API로 바로 읽을
수 있다고 가정하지 않으며 내장 괄호 색과 확장 색의 완전한 일치는 출시
약속에서 제외한다.

다음 검증 결과가 상세 설계 확정과 MVP 구현 진입의 선행 조건이다. 현재
[상세 설계안](detailed-design.md)은 미검증 표시값을 고정하지 않은 초안이다.

| 기술 검증 | 통과 조건 | 실패 시 조정 |
| --- | --- | --- |
| 언어별 범위 분석 | 정상·미완성·오류 입력에서 범위와 종류를 구별하고, 복구 후 오래된 강조를 지움 | 해당 구문 지원 축소 또는 파서 교체 |
| 경계 장식 | 실제 편집기에서 탭·접힘·줄바꿈의 경계가 코드와 어긋나지 않고 화면 밖 배경이 과하게 남지 않음 | 보이는 행의 시작·끝 표시와 상태 표시줄로 축소 |
| 내장 표시 공존 | 선택·검색·진단·디버거 표시가 읽힘 | 배경 제거 또는 경계 중심 표시 |
| 파서 실행 환경 | 확장 호스트와 시험용 VSIX에서 정상 실행 | 의존성 교체, 웹 지원 별도 출시 |

### 검토 결과와 적용 순서

[Document Review](https://skills.pydemia.ai/skills/document-review)의
사실·검증 상태 구분 기준으로 프로토타입과 목표 동작을 대조했다.
2026-10-01에 확인한 Hub revision은 `fab5b075d3e1`이다.

- **확인 완료:** 범위 분석 자동 테스트 13개, 타입 검사, 빌드, 확장 호스트의
  활성화·명령 실행, VSIX 생성·격리 설치·패키지 내용의 호스트 실행.
  합성 10,000행의 분석·범위 선택 시간은 참고값이다.
- **미확인:** 실제 장식 위치와 기존 표시와의 공존, 커서 이동부터 장식
  반영까지의 지연. 확인한 검사만 통과로 기록한다.
- **우선 1 · 정확성:** JS/TS 구문 진단, 엄격한 JSON 파싱, Python 오류
  노드 기준과 `Scope: 구문 확인 불가` 문구를 적용했다. 자동 테스트는
  오류·복구를 확인했으며, 실제 편집기의 빠른 수정에서 오래된 장식이
  남지 않는지는 추가 검사한다.
- **우선 2 · 화면:** 탭·접힘·줄바꿈·고대비 테마와 선택·검색·진단·디버거
  표시를 실제 편집기에서 비교한다. 범위 배경은 보이는 영역에 제한할
  필요가 있는지 측정하고, 가독성을 해치면 경계 중심으로 축소한다.
- **우선 3 · 실행 환경과 성능:** VSIX에 필요한 의존성이 포함되는지
  확인하고, 10,000행에서 장식 반영까지의 p95를 측정한다. 긴 단일 행과
  깊은 중첩을 포함해 20,000행·2MB 제한 후보를 재평가한다.

우선 1~3의 통과 조건과 제약을 기록하기 전에는 기술 검증이나 상세 설계를
완료로 표시하거나 팔레트·나머지 명령 구현을 출시 가능한 MVP로 분류하지 않는다.

## 개발 단계와 완료 기준

| 단계 | 산출물 | 다음 단계 진입 기준 |
| --- | --- | --- |
| 기술 검증 | JS/TS·Python·JSON 샘플, 범위 분석·장식 실험 | 검토 결과의 우선 1~3과 위 검증표의 지원 범위·제약 확정 |
| 상세 설계 | 언어별 범위 규칙, 설정 명세, 색상 비교, 이벤트 처리 설계 | 오류·미지원·대용량 상태까지 동작 정의 |
| MVP 구현 | 들여쓰기, 현재 범위, 팔레트, 상위 범위·이동 명령 | 아래 기능 검증 기준 충족 |
| 출시 검증 | 테마·플랫폼·확장 공존 결과, VSIX, 사용 설명 | 실제 편집기 검증과 지원 범위 문서화 |

MVP에는 전체 텍스트 감광, 독자적인 모든 괄호 색칠 엔진, 태그 언어 전체
지원, AI 코드 분석, 자동 들여쓰기 수정, 팀 공유 팔레트 서버를 포함하지 않는다.

검증은 분석 로직의 자동 테스트와 Extension Development Host에서의 실제
장식·입력 검증을 구별해 기록한다. 아래 수치는 성능 목표 제안이며 측정
결과가 아니다. 측정 장비·VS Code 버전·문서 규모를 결과에 함께 기록한다.

- 정상 코드에서 선택한 범위의 시작·끝이 기준 샘플과 일치한다.
- 문자열·주석 속 괄호와 Python 인자 정렬이 가짜 블록을 만들지 않는다.
- 미완성·오류 입력에서 잘못된 대규모 강조가 남지 않고 입력 복구 후
  갱신된다. 정상 최상위·미지원·구문 오류·분석 실패의 상태가 구별된다.
- 팔레트 미리보기 취소, 설정 위치별 초기화, 테마 전환이 정상 동작한다.
- 분할 편집기·여러 커서·접힘·줄바꿈·탭 혼합을 실제 편집기에서 확인한다.
- 10,000행 기준 샘플에서 분석 완료 후 커서 이동부터 장식 갱신까지
  p95 50ms 이하를 목표로 한다. 최초 분석 시간은 별도 측정한다.
- 초기 분석 제한 후보는 20,000행 또는 2MB 초과다. 긴 단일 행, 깊은 중첩,
  분석 시간·장식 개수 제한을 함께 측정한 뒤 출시 기본값을 정한다.
- 종료·문서 전환·빠른 연속 입력 후 오래된 장식과 분석 결과가 남지 않는다.

사용성 검증에서는 확장 꺼짐·기본 설정·새 확장 설정으로 같은 중첩 샘플을
읽고 블록 시작·끝을 찾는 과제를 비교한다. 시간과 오답, 방해된 표시를
기록하며 관찰 전에는 생산성 향상률을 제시하지 않는다.

## 적용 스킬과 미확정 결정

[Product UI/UX Design](https://skills.pydemia.ai/skills/product-ui-ux-design)의
요구사항 구분, 실제 제품 참고, 사용자 흐름, 표시 상태, 접근성, 구현
인계 기준을 적용했다. Hub에서 확인한 source revision은 `2d0786579661`이다.
VS Code 확장이므로 웹 페이지 레이아웃·모바일 전환·web-publishing 단계는
이번 기획 범위에 적용하지 않았다.

제품 가칭, 첫 출시 언어 범위, Balanced 기본 모드는 승인된 설계 기준이다.
선·배경의 실제 표시 방식, 언어별 파서 선택, 최소 VS Code 버전, 정확한
팔레트 값, 성능 제한값은 기술 검증과 상세 설계에서 확정한다. 현재 manifest의
VS Code `^1.138.0`과
20,000행·2MB 제한은 프로토타입 값이다. 현재 문서는 사용자가 승인한
설계나 출시 검증을 마친 구현으로 취급하지 않는다.
